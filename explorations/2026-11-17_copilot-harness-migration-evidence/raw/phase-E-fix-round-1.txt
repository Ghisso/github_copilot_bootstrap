=== 3. MINOR (tests): four properties that had no test able to fail. New tests (tests/test_hook_gates.py):
  a. test_the_subagent_hook_is_not_hijacked_by_a_module_named_json[repository-root | subfolder | pythonpath]
     a json.py that writes a sentinel file when imported is put in the repository root, in the folder the hook runs in, or on PYTHONPATH. The sentinel must not appear, and the answer must be the normal one.
  b. test_the_subagent_hook_warns_and_exits_zero_when_python_exits_non_zero
     a stub python3 first in PATH that exits 1: exit 0, no stdout, stderr exactly "WARN subagent-context: internal error; skipping context\n".
  c. test_the_subagent_hook_treats_closed_standard_input_as_malformed
     standard input closed (`<&-`): exit 0, no stdout, stderr exactly "WARN subagent-context: malformed hook input; skipping context\n".
     This needed a one-line change in shared/hooks/scripts/subagent-context.sh. Before it, closed input gave a Python traceback (`sys.stdin` is None) and then the generic "internal error" warning, still exit 0. Now `json.loads(sys.stdin.buffer.read() if sys.stdin else b"")` treats it as input that is not a JSON object, with no traceback.
  d. test_the_session_mode_is_accepted_only_for_the_copilot_client_and_only_by_it now compares the whole stderr line for each of its 8 cases, for example "WARN reporting-reminder: unsupported mode: prompt" for `prompt github-copilot`, not only the prefix.
Found while writing the mutation checks, and fixed in the tests:
  - test_the_subagent_hook_warns_and_exits_zero_when_python_is_missing only searched stderr for "python3", which bash's own "command not found" also contains; removing the presence check survived. It now compares the exact warning. The mutation is now killed.
  - the two budget boundary tests read the limit from the validator, so changing the limit to 2049 moved them along and only the pin test failed. They now use the literal 2048.
  - _run_subagent_context now has timeout=30 (the hook file's timeout is 10 s), so a hook that blocks on a named pipe fails its test instead of hanging the suite.

  scripts/check_copilot_runtime.py:
    - session_reminder: the middle branch (the reminder found in a later message, which only changed the message text) is gone. The `missing` list stays: its text tells a reader whether the heading, the fixed line, or both are absent, and that separates "the hook did not run" (both) from "the guidance file is missing or over the limit" (heading only, as in the controls no-guidance-file and oversized-guidance). That information is not recoverable from a plain "lacks" line.
  tests/test_check_copilot_runtime.py: the case the-reminder-came-after-another-message is kept, with the new message.
