settings source, and can the probe tell when it does not?

deliberately wrong setup; everything else is the shipped probe on the Phase C guards. Each control ran
twice (rounds 1 and 2 below). Only the camel lines are shown.

Positive proof of camelCase events: with the guards of Phase B, the camel-deny and camel-ask lines FAIL
(phase-C-probe-output.txt, section A). That can only happen if the runtime sees camelCase event names,
because the same guards pass the same steps under PascalCase in the main session (F4).

  restore-root-adapters.sh, which copied the PascalCase file back from .claude/bootstrap-root during the
  session. camel-events-renamed FAILS (state read after the run). The deny lines still PASS, because the
  restored PascalCase file denies: a check on denies alone would have passed in a wrong setup.

  from .claude/settings.json) and camel-events-renamed FAILS (settings.json is back). The deny lines PASS
  (the Claude source denies), and the asks raise 2 questions instead of 1.
- no-rename: Claude settings off, no event renamed. camel-events-renamed FAILS; the deny lines PASS.
