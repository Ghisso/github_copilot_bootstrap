== 3. The `tr` form: what is known ==
POSIX defines `[c*]` in the second set as padding to the length of the first set. The form was run on GNU tr
only. No macOS or BSD machine here. A second tr implementation exists on this machine (/usr/bin/busybox, BusyBox
v1.36.1, no install needed). Command: printf 'a\tb\nc' | <tr> '\001-\037' '[ *]' | od -c
  GNU tr 9.4              : 0000000   a       b       c
  busybox tr (1.36.1)     : 0000000   a   ]   b   ]   c
For comparison, other forms of the same mapping:
  bare ' ' on GNU tr      : 0000000   a       b       c
  bare ' ' on busybox tr  : 0000000   a       b       c
  31 literal spaces, GNU  : 0000000   a       b       c
  31 literal spaces, busybox: 0000000   a       b       c
FINDING: BusyBox tr does not read `[c*]` in the second set. It pads with the set's last character, so each control
character becomes `]` instead of a space. The result is still valid JSON, but it is not a space, and the claim
"on GNU and BSD tr alike" that was in the code comment was wrong. The code is unchanged in this round, as asked. The
comment in _lib-frontmatter.sh now says: POSIX defines `[c*]` as padding; run on GNU tr only; BusyBox 1.36.1 prints
`]` for each character. The T3 row says the same. The bare form `' '` and a 31-space second set both give spaces on
GNU and BusyBox; whether BSD tr pads the bare form was not run. A decision for the coordinator: keep `[ *]`, or go back
to the bare `' '`, or use the 31-space set (portable by construction, no padding rule).

Fix round 1, part 2 (2026-11-17): the second `tr` set is 31 spaces
=============================================================================
Decision: the second set has one space for each of the 31 characters, so the mapping is position for position and
needs no padding rule. The form `printf -v spaces '%31s' ''` is a bash builtin (since 3.1), so it needs no fork and
no hand-counted literal; the simpler bare `' '` was not used because it depends on the padding rule of each `tr`.
Final code (shared/hooks/scripts/_lib-frontmatter.sh):

json_escape() {
  local spaces
  printf -v spaces '%31s' ''
  printf '%s' "$1" | tr '\001-\037' "$spaces" | sed 's/\\/\\\\/g; s/"/\\"/g'
}

The comment above it says: one space for each of the 31 characters, position for position, no padding rule (POSIX
leaves a shorter second set unspecified, and BusyBox `tr` does not read `[c*]`); run on GNU `tr` and BusyBox `tr`
1.36.1; not run on macOS or BSD `tr`. The T3 row in docs/target-mapping.md says the same.

== 1. New test: test_json_escape_gives_tr_a_second_set_of_exactly_31_characters ==
A stub `tr` first in PATH logs one line, exits 64 unless it got exactly two arguments, the first `\001-\037` and
the second exactly 31 characters long, and otherwise runs the real `tr`. The test asserts that the stub was used
once, printed nothing on stderr, and that deny_pretool gave valid JSON with "tab here newline" (top level and nested).
The stub is 5 lines of shell (the test body is about 30 lines with its asserts). Source:

def test_json_escape_gives_tr_a_second_set_of_exactly_31_characters(
    tmp_path: Path,
) -> None:
    """A shorter second set (`' '`, `'[ *]'`) works on GNU `tr` but leans on a padding
    rule that POSIX leaves unspecified and BusyBox `tr` reads differently. A stub
    `tr` first in PATH refuses anything but the equal-length form, then runs the
    real `tr`, so a Linux host with GNU `tr` can still see that regression."""
    real_tr = shutil.which("tr")
    assert real_tr is not None
    tools = tmp_path / "bin"
    tools.mkdir()
    log = tmp_path / "tr-calls"
    stub = tools / "tr"
    stub.write_text(
        "#!/bin/sh\n"
        f"echo called >> {shlex.quote(str(log))}\n"
        '[ "$#" -eq 2 ] && [ "$1" = \'\\001-\\037\' ] && [ "${#2}" -eq 31 ] \\\n'
        "  || { printf 'stub tr: refused: %s args, first %s, second set %s characters\\n'"
        ' "$#" "$1" "${#2}" >&2; exit 64; }\n'
        f'exec {shlex.quote(real_tr)} "$@"\n',
        encoding="utf-8",
    )
    stub.chmod(0o755)
    env = {k: v for k, v in os.environ.items() if k != "TARGET_ID"}
    env.update(PATH=f"{tools}:{env['PATH']}", TARGET_ID=COPILOT)

    result = subprocess.run(
        ["bash", "-c", 'set -eu; . "$1"; shift; "$@"', "bash"]
        + [
            str(SCRIPT_SRC / "_lib-frontmatter.sh"),
            "deny_pretool",
            "tab\there\nnewline",
        ],
        text=True,
        capture_output=True,
        check=False,
        env=env,
    )

    assert log.read_text(encoding="utf-8") == "called\n", "the stub tr was not used"
    assert result.stderr == ""
    answer = json.loads(result.stdout)
    assert answer["permissionDecisionReason"] == "tab here newline"
    assert (
        answer["hookSpecificOutput"]["permissionDecisionReason"] == "tab here newline"
    )
