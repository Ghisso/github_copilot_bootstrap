# Hook dispatcher and guardrail scripts

Source, tests, and the policies under `shared/policies/` outrank this page.
Where this page and the code disagree, the code is right.

## One script tree, four hook configurations

All guardrail logic lives in `shared/hooks/scripts/`, installed into a
consumer as `.claude/hooks/scripts/`. Each target has its own native hook
configuration, all generated by `scripts/generate_targets.py`:

| Target | Hook configuration | How it reaches the scripts |
|---|---|---|
| GitHub Copilot | `.github/hooks/hooks.json` (copied from `shared/hooks/hooks.json`) | `run-hook.sh <script> [args]` |
| Claude Code | `.claude/settings.json` | `run-hook.sh <script> [args]` |
| OpenAI Codex | `.codex/hooks.json` | `run-hook.sh <script> [args]` |
| Google Antigravity | `.agents/hooks.json` | `antigravity-pretool.py` directly, a Python bridge that normalizes Antigravity's payload and invokes the same guards |

`run-hook.sh` is the dispatcher. It resolves the repository root from its
own location first, then from `GITHUB_WORKSPACE`, `WORKSPACE_FOLDER`,
`VSCODE_CWD`, or `PWD`, then from `git rev-parse --show-toplevel`, and
finally executes `.claude/hooks/scripts/<name>` under `/bin/bash`. A
missing script name exits 2, which denies the tool call on runtimes that
key blocking on exit status; a missing script file only warns and exits 0,
so an incomplete install degrades rather than blocking every tool call.

## Events and what runs on them

Claude Code and Codex get the same shape:

- **SessionStart**: `state-sync.sh pull` (pull nested AI state),
  `session-log.sh`, `session-start-state.sh` (report the active plan and
  phase), `context-mode-dispatch.sh sessionstart`.
- **PreToolUse**, split by matcher so the safety lane stays narrow:
  `Edit|Write` runs `protect-files.sh`; `Bash` runs
  `pretool-bash-guard.sh`; the wildcard matcher runs only the optional
  `context-mode-dispatch.sh` observability hook; and the MCP tool
  `mcp__openwiki__openwiki_begin` runs `openwiki-guard.sh pre`.
- **PostToolUse** on `Bash`: `record-branch-state.sh`,
  `context-mode-dispatch.sh`, `reporting-reminder.sh late-report`; on
  `openwiki_begin`: `openwiki-guard.sh post`.
- **Stop**: one ordered wrapper, `claude-stop.sh` or `codex-stop.sh`, that
  runs session logging, the session-log freshness check, then
  `state-sync.sh checkpoint` and `state-sync.sh publish` in sequence. Each
  child failure is logged and skipped, never fatal. Codex's Stop also runs
  `openwiki-guard.sh post`.

Two per-host differences matter. Claude Code fires `PostToolUseFailure`
when an MCP tool returns an error, so the OpenWiki restore is wired there
too. Codex fires nothing on an MCP tool error, so the payload-free
`openwiki-guard.sh post` at Stop is the adaptation, and Codex additionally
runs `state-sync.sh push` plus `reporting-reminder.sh prompt` on
`UserPromptSubmit` and `state-sync.sh checkpoint` on `SessionEnd`.

GitHub Copilot's `hooks.json` has no matchers, so it lists `protect-files.sh`,
`git-protection.sh`, `enforce-branch-state.sh`, `enforce-commit-gate.sh`,
and `enforce-pr-gate.sh` individually under `PreToolUse`, with the same
SessionStart, PostToolUse, PreCompact, and Stop scripts. Antigravity wires
only a `*` PreToolUse bridge; lifecycle hooks are deliberately absent there.

## The ordered Bash safety lane

Hosts start sibling hooks concurrently, so `pretool-bash-guard.sh` exists to
impose order. For a Bash tool payload it runs, in sequence,
`protect-files.sh`, `git-protection.sh`, `enforce-branch-state.sh`,
`enforce-commit-gate.sh`, and `enforce-pr-gate.sh`, piping the same payload
to each. The first guard that prints a decision wins and the wrapper exits;
a guard that exits non-zero or prints anything other than a well-formed
`deny` or `ask` decision makes the wrapper fail closed.

Decisions are JSON `hookSpecificOutput` objects with `permissionDecision`
`deny` or `ask` and a reason. `fail_closed` in `_lib-frontmatter.sh` is the
shared error path: it appends a timestamped line to
`.claude/session_logs/hooks-errors.log`, emits a deny whose reason starts
with `hook could not evaluate the request safely, denying:`, and exits 2.
An empty payload is allowed through (some events send nothing); a present
but unparseable payload fails closed.

## The guards

**`protect-files.sh` / `protect-files.py`** classifies one PreToolUse
payload for mutations of protected files: credential-shaped names (`.env`,
`.env.*`, `credentials*`), `uv.lock`, and the hook configuration files
(`.github/hooks/hooks.json`, `.claude/settings.json`, `.codex/config.toml`,
`.codex/hooks.json`). It understands Edit and Write payloads, patch-format
blocks, and shell commands, including redirects, simple mutators such as
`rm` and `tee`, and variable substitution tricks. Read-only commands pass.
A protected mutation is denied on Codex and Antigravity and turned into an
`ask` on the other hosts. The shell wrapper runs the Python classifier with
plain `python3`, not `uv run`, so protection works before a project
environment exists, and fails closed with a diagnostic if the classifier
itself errors.

**`git-protection.sh`** denies destructive Git forms anywhere in a Bash
command: `git reset --hard`, force pushes (`-f`, `--force`,
`--force-with-lease`), `git push --mirror`, `git checkout --`,
`git restore --source`, `git clean` with both `f` and `d`, and deleting
`main` or `master`. It tokenizes each `git` clause up to the next unquoted
shell operator so a later command's flags cannot be misattributed, and it
lowercases tokens so case cannot evade it. Use `git restore -- <path>` where
you would otherwise reach for `git checkout -- <path>`.

**`enforce-branch-state.sh`** gates branch creation. A new branch must be
named `<plan_name>_implementation`, be created from a clean `dev` checkout,
and correspond to `.claude/plans/<plan_name>.md` with `type: big-plan`,
exactly one `status` field, and a status of `planning` or `in-progress`. A
branch created in another repository through `-C`, `--git-dir`, or
`--work-tree` is judged by that repository, not this one.

**`enforce-commit-gate.sh`** gates `git commit`. It stands down for commits
aimed at the nested `.claude` AI-state repository (which `state-sync.sh`
makes constantly) and for commits explicitly redirected at another
repository; a compound command that mixes those with an outer commit is
still gated in full. Otherwise it requires an implementation branch and, for
an ordinary commit, `assert_commit_invariants`: the current small plan,
findings report, verify receipts, LEARN evidence, and closeout session log
described on the deterministic verification page. Bypass subjects
(`fixup!`, `squash!`, and `chore(typo):` or `docs(typo):` over eligible
documentation paths only) skip the plan ceremony but not the branch check,
and are ledgered by `record-commit-closeout.sh`.

**`enforce-pr-gate.sh`** gates `git push` and `gh pr create`. A push aimed
at the nested repository or another repository stands down, but a pull
request never does, because `gh -R` names an owner and repository, not a
filesystem path. Pushes require an implementation branch and pass
`assert_push_invariants`; pull requests additionally require `--base dev`
and pass `assert_closeout_invariants`. A chained commit-and-push is refused
with an explanation, because the gate evaluates the HEAD that exists before
the command runs.

**`openwiki-guard.sh` / `openwiki-guard.py`** wraps the single OpenWiki
tool that writes outside `openwiki/**`. `pre` denies `mode: "init"`, a root
that is not this repository, and a repository without
`openwiki/INSTRUCTIONS.md`, and otherwise snapshots root `AGENTS.md`,
`CLAUDE.md`, and the OpenWiki workflow path into
`.claude/.cache/openwiki-guard/`. `post` restores them byte for byte,
removes an adapter that did not exist before, refuses a symlinked path, and
exits 2 without touching a file that changed concurrently.

**`reporting-reminder.sh`** is advisory only. It fails open on any internal
error and adds reminder context about user-facing reporting after a Bash
tool call or, on Codex, on prompt submit.

## Recording hooks

`record-branch-state.sh` runs after every Bash call. When a branch was just
created, it writes `originating_branch`, `implementation_branch`,
`started_at`, and `current_phase` into the big plan and activates the first
planned phase; an unsafe phase value or unexpected status is reported rather
than written. `record-commit-closeout.sh` is invoked from the outer Git
`post-commit` hook path to advance `current_phase` after a completed phase
commit and to ledger bypass commits in
`.claude/session_logs/hooks-bypass.log`; merges never infer a phase
transition. `session-log.sh` appends session events to
`.claude/session_logs/hooks-sessions.log`, translating between Claude
Code's snake_case and Codex's camelCase payload keys.

## Git hooks as the second layer

`shared/hooks/git-hooks/` holds `commit-msg`, `pre-push`, and `post-commit`,
activated by `state-sync.sh` through the repository's hooks path. Git always
runs them from the working-tree root with the commit message or ref lines as
input, so, unlike the PreToolUse gates, there is no command string to
classify or evade. `commit-msg` and `pre-push` re-check the same invariants
as the PreToolUse gates; `post-commit` best-effort pushes nested AI state
after every outer commit and can never fail the commit, because Git ignores
its exit status and `state-sync.sh` is warn-never-fail.

## Logs

- `.claude/session_logs/hooks-errors.log`: fail-closed denials, Stop wrapper
  child failures, `git-protection` and `state-sync.sh` warnings. Local
  only; `state-sync.sh` gitignores and untracks it in the nested repository.
- `.claude/session_logs/hooks-bypass.log`: every successful commit-gate
  bypass. Tracked, and publication is blocked until bypasses are
  acknowledged in the big plan.
- `.claude/session_logs/hooks-sessions.log` and
  `hooks-commit-closeout.log`: session events and the commits the closeout
  recorder has already processed.

## Representative tests

`tests/test_hook_gates.py` and `tests/test_lifecycle_hooks.py` exercise the
gates against real temporary repositories, including the plan-frontmatter
assertions, receipt relations, and the Bash 3.2 array idiom the scripts must
keep for macOS. `tests/test_openwiki_guard.py` covers each `pre` denial
(init, foreign root, missing root, missing marker), the snapshot on allow,
byte-for-byte restore, removal of an adapter that was absent before, and the
exit-2 path for a concurrently edited adapter.
`tests/test_protect_files_scoping.py` covers the classifier's scoping rules.
